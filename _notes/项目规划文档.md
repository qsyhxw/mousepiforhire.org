# MousePIForHire.org 页面建设规范

本文档用于统一 `mousepiforhire.org` 后续所有页面的规划、创建、核验与维护标准。

它的作用是：

- 盘点当前已经完成的页面
- 明确第一阶段仍遗漏的页面
- 规划后续可继续拆分的新页面
- 统一未来建页时的 SEO、事实核验、图片、本地化与输出规范

后续新增页面时，默认都以本文档为执行标准，除非有新的专项要求覆盖。

## 3. 新页面统一建设标准

后续所有新页面，默认遵循以下规则。

### 3.1 事实来源与核验标准

1. 严禁使用本站自身内容作为事实来源。
2. 所有可核验陈述，在写入页面前都应先检索外部公开来源。
3. 在条件允许时，每条关键事实尽量至少使用 2 个独立来源交叉验证。
4. 来源优先级如下：
   - 官方公告 / 官方补丁说明 / Steam 商店页 / 开发者回复 / 官方 FAQ
   - 专业媒体、开发者访谈、权威攻略站
   - 社区维基、Steam 指南、Reddit、视频等
5. 若多个来源互相冲突，以最新的官方渠道为准。
6. 若证据不够强，就使用保守措辞，不要把猜测写成确定事实。
7. 严禁杜撰：
   - 武器名称
   - 任务名称
   - 关卡数量
   - 解锁条件
   - 收集品数量
   - Boss 名称或机制
   - 版本变化

### 3.2 SEO 标准

1. `Title` 与 `Meta Description` 长度要符合 Google SEO 习惯。
2. 标题优先覆盖主搜索意图或核心关键词。
3. 描述应说明页面能解决什么问题，而不仅仅重复标题。
4. `canonical`、Open Graph、Twitter Meta、JSON-LD 保持现有站点风格一致。
5. 页面中应合理布局内链，服务于搜索意图和站内权重传递。

### 3.3 页面结构与设计标准

1. 优先复用首页和现有页面的头部、页脚、字体、颜色、布局体系。
2. 保持当前站点的视觉语言一致：
   - noir / 1930s / guide-site 风格
   - 深色底
   - 金色强调
   - 衬线标题 + 打字机标签 + 正文字体
3. 尽量复用站内已存在模块：
   - Hero
   - signal pill / badge
   - FAQ
   - CTA
   - 推荐阅读
   - Version Note
   - 内链卡片
4. 不随意新造一套完全不同的页面系统，除非确有必要。

### 3.4 站内内链标准

1. 所有页面应根据主题自然添加站内内链。
2. 内链优先指向用户下一步最可能需要的支持页。
3. 常见内链目标包括：
   - `/guide/beginners-guide/`
   - `/weapons/`
   - `/collectibles/`
   - `/upgrades/schematics-locations/`
   - `/trophies/`
   - `/trophies/platinum-guide/`
   - `/walkthrough/`
   - `/bosses/`
   - `/tips/`
   - `/news/`（建好后）

### 3.5 正文外链标准

1. 页面正文中不展示来源链接列表。
2. 页面正文中不出现“参考资料区”“引用来源区”“外站出处按钮”。
3. 事实来源只存在于工作过程输出中，不写入页面 HTML 正文。
4. head 中现有的字体、OG、schema 等模板级外链可继续沿用。

## 4. 图片与媒体规范

### 4.1 基本原则

1. 新页面不应默认只有纯文字，适合配图时应加入图片。
2. 一般建议：
   - 1 张主图
   - 1 到 3 张章节配图
3. 页面 HTML 中只允许引用本地图片路径。
4. 禁止在页面里直接保留第三方图片 URL。

### 4.2 图片优先级

1. 自己实际游戏截图
2. 官方宣传图 / 官方商店图 / 官方素材
3. 可明确公开访问的相关截图
4. 第三方图源，仅在没有更好方案时谨慎使用

### 4.3 外部图片转本地流程

如果图片来自外站，必须先完成以下流程：

1. 下载到本地
2. 统一重命名
3. 放入正确分类目录
4. 页面改为引用本地路径
5. 添加准确 `alt`

### 4.4 图片目录与命名

建议目录结构：

```text
/images/mouse-pi-for-hire/
  /weapons/
  /collectibles/
  /newspapers/
  /trophies/
  /home/
  /steam-screenshots/
```

建议命名方式：

```text
mouse-pi-weapons-boss-arena-01.jpg
mouse-pi-newspapers-route-01.jpg
mouse-pi-home-tool-upgrades-01.jpg
```

### 4.5 图片质量要求

每张图片应具备：

- 准确简洁的 `alt`
- 合理尺寸
- 尽量使用 Web 友好的格式
- 必要时有图注

同时注意：

- 尽量避免在多个页面重复刷同一张图
- 如果暂无足够安全或可靠的图片，可减少数量，但不乱补无关图

## 5. 内容表达与诚实性要求

1. 证据强的内容，可以直接陈述。
2. 证据中等的内容，要用保守、务实的语气。
3. 证据不足或冲突明显的内容，应：
   - 省略
   - 在工作输出中标为存疑
   - 或在正文中改为诚实但模糊的描述
4. 特别要避免伪确定性的场景包括：
   - 资料冲突的精确数量
   - 基于单一来源得出的最优打法
   - 补丁敏感的 bug 与机制
   - 未来可能改动的版本规则

## 6. 新建页面时的标准输出格式

后续每次创建新页面时，工作输出继续沿用 3 段式结构。

### Part 1：事实校对表

使用以下表头：

| Claim | Verdict(✅正确 / ❌错误 / ❓存疑) | Corrected（若需要） | Evidence1（链接 + 出处名 + 日期/版本） | Evidence2 | Notes | Confidence(0–1) |

要求：

- 每条事实都要有证据或被标为存疑
- 标注来源新鲜度
- 若有冲突，在 `Notes` 中说明
- 专有名词保留英文原文

### Part 2：已校对的页面内容

至少包括：

- SEO Title
- Meta Description 草稿
- H2 / H3 页面结构
- 与事实校对表一致的正文内容概要
- 实际使用的本地图片，或建议插图位置

### Part 3：风险与版本提示

必须附带：

1. High-Risk 信息清单
2. 内容优化建议
3. 版本差异提示

## 7. 实际建页操作流程

以后创建页面时，建议按以下顺序执行：

1. 先确认该页面是否已经存在
2. 不使用本站内容作为证据
3. 检索并交叉核验事实
4. 复用既有 HTML 模板体系
5. 只使用本地图片
6. 加入合理内链
7. 对证据强弱做诚实区分
8. 自检页面正文中是否暴露外部来源链接
9. 在最终工作输出中列出高风险信息
